## 2. Multilingual System Evaluation & Migration Plan (Requirement 9)

### 2.1 Current System: WPML
- **Architecture:** Creates separate post IDs per language linked via relational database tables (`wp_icl_translations`, `wp_icl_strings`).
- **Downsides:**
  - Adds ~15 custom database tables.
  - Can generate 20–50 additional SQL queries per page load.
  - High memory usage (often requiring 256MB+ PHP memory limit).

### 2.2 Proposed Alternative: Polylang (with Polylang for WooCommerce)
- **Architecture:** Uses WordPress core taxonomy terms (`language`) to associate translated posts and products.
- **Advantages:**
  - Zero custom tables (utilizes core `wp_terms` and `wp_term_relationships`).
  - Negligible database overhead and significantly faster TTFB.
  - Full compatibility with native WordPress REST API and Yoast SEO.

### 2.3 Migration Risk Analysis
1. **URL Stability:** Existing URLs like `/en/` and language slugs must be preserved to avoid 404 errors and losing search ranking.
2. **WooCommerce Product Associations:** Translation links between Persian and English equipment specifications must remain intact.
3. **Shortcode & Meta Integrity:** Custom fields (`_project_client`, `_project_capacity`, etc.) must be marked as synchronized across languages.

### 2.4 Step-by-Step Migration Plan
1. **Staging Backup:** Full database dump (`wp-content` + SQL) prior to changes.
2. **Data Export:** Export existing WPML string translations and post associations via WP All Export or native WP-CLI.
3. **Install Polylang & "WPML to Polylang" Migration Bridge:** Run automated converter to migrate language taxonomy terms.
4. **Synchronize Custom Post Types & Meta:** Ensure `projects` and `product` types are enabled under Polylang settings.
5. **Verify Permalinks & 301 Redirects:** Confirm URL structure matches the original configuration (`/en/` prefix or subdomain).

## 4. Key Engineering Features

### 4.1 Custom Project Technical Table Builder
- Embedded directly into the `projects` CPT without third-party plugins.
- Stores data as a clean JSON structure in `_project_technical_table`.
- Administrators can dynamically add/remove rows and columns and edit cell contents directly in the post editor.
- **Frontend Output:** Semantic HTML `<table>` wrapped in a responsive container with horizontal scrolling and scroll cue hints for mobile devices.

### 4.2 Safe Native Excel (.xlsx) Import
- Integrated into the project table admin UI.
- Unpacks OpenXML archives using standard PHP `ZipArchive` and `SimpleXMLElement`.
- **Security Protections:**
  - Strict file type and MIME validation.
  - Formula injection mitigation: strips or prefixes leading `=`, `+`, `-`, `@`.
  - Disables external entity loading (`LIBXML_NONET`) to prevent XXE attacks.
  - Escapes all data upon rendering.

### 4.3 WooCommerce B2B Industrial Integration
- Keeps full compatibility with WooCommerce products, categories, and inventory.
- Replaces traditional consumer checkout friction with a **B2B Engineering Quotation / RFQ** workflow.
- Fast category and equipment type filtering on the catalog page.

### 4.4 SEO & Yoast Integration
- Emits proper `wp_head()` and `wp_footer()` hooks.
- Delegates OpenGraph, Twitter Cards, Canonical links, and JSON-LD schema graphs exclusively to **Yoast SEO Premium** to eliminate redundant markup.
- Semantic HTML headings (`h1`–`h4`) and accessible landmark tags (`<header>`, `<main>`, `<nav>`, `<aside>`, `<footer>`).

### 4.5 Performance & Accessibility
- Zero page builder dependencies (replaces ~1.5MB of Elementor CSS/JS).
- Vanilla JavaScript (<12KB) loaded with `defer`.
- Google Maps iframe loaded with `loading="lazy"` exclusively on the Contact page.
- WCAG 2.1 AA compliant: 4.5:1 color contrast, visible `:focus-visible` rings, screen reader text, keyboard accessible drawer and modal dialog.
